NBS Conformance Tests
======================

The "Pxxx.BAS", "Pxxx.ok", and "Pxxx.eok" files in this location come from the
"bas55" package (ECMA-55 Minimal BASIC System), by Jorge Giner
Cordero, version 2.0 under the MIT license and made available at
https://jorgicor.niobe.org/bas55. See "COPYING" in the original package.

The "Pxxx.BAS" programs themselves are the formal NBS (National Bureau of
Standards, now NIST) conformance test suite, published in 1978 in
NBSIR reports 78-1420-1 through -4 — public-domain text from the
U.S. government. They were written and maintained over the years by John
Gatewood Ham, author of the "ECMA-55 Minimal BASIC Compiler" —
http://buraphakit.sourceforge.net/BASIC.shtml, with additional
corrections by Emmanuel Roche and Jorge Giner Cordero himself.

The ".ok" files (expected output) and ".eok" files (expected error output)
are generated by the bas55 implementation itself. They are not the
official NBS answer key (which would require human judgment line by line,
following the original manual), but rather a mature implementation that
has been tested for years against these same programs.


How this project uses these tests
---------------------------------

"tests/test_nbs.cpp" executes each "Pxxx.BAS" through the interpreter and
compares standard output with "Pxxx.ok". When an error is expected
("Pxxx.eok" is not empty), the exact error message text is not compared;
only whether an error occurred or not is checked. Error messages are
"implementation-defined" (Appendix 4 of the ECMA-55 standard),
so the standard text from bas55 does not, by definition, match this
project.

"make nbs" compiles and runs this test suite.


Known and deliberate divergences from bas55
--------------------------------------------

Some tests fail intentionally because this project chose to follow a
different path from bas55 on points that the standard leaves open:

- Lowercase letters in source code ("P204", "P205"): the standard defines
  "letter" as uppercase A-Z only. bas55 rejects lowercase letters outside
  editor mode; this project accepts them and normalizes them to uppercase.
- Unary sign after an operator ("P038", "pow", e.g.: "4^-2",
  "1+-3"): the bas55 manual itself acknowledges that this is an extension
  of its own, "not required or accepted by the standard". This project,
  with no additions beyond the standard, rejects it.
- Uninitialized variable ("P023", "P028"): bas55 (outside debug mode)
  assumes zero/empty string; this project treats it as a fatal error,
  following the recommendation in the standard text (section 7.6).

The remaining failures (numeric formatting in extreme precision cases,
all in functions that the NBS itself labels as "informative only, since
the ANSI standard does not mandate any accuracy for supplied-functions")
are floating-point noise between implementations, not compliance gaps.
